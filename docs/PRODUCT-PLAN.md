## 2. 产品定位

**面向任何行业的个人日常工作台**。不是四象限待办，而是「容量约束下的目标管理」：

> 示例数据使用安全团队场景用于演示；产品能力不依赖行业。

> 年/Q 季度规划（计划人日）→ 本周安排（关联任务/项目）→ 项目工作项自动排期 + 全局里程碑进度。

五条原则：

1. **容量先行**：先看可用人日 / 已占用 / 剩余，再排季度任务，超载立刻提示；
2. **两层节奏**：季度管方向与容量，周管落地；
3. **一眼判断**：进度条、状态色、剩余天数、逾期区；
4. **录入零摩擦**：⌘K 跳转、行内新建、AI 自然语言创建；
5. **克制**：只保留规划闭环 + 笔记/链接，不做大而全。

## 3. 信息架构

顶部全局栏：`‹ 2026 › Q1 Q2 Q3 Q4 ｜ ⌘K ｜ AI ｜ 提醒 ｜ 皮肤 ｜ 设置 ｜ 收起`

左侧导航按内容分两组，小字标签是分组标题：

- **规划与推进**：季度规划 / 本周安排 / 项目（全局）
- **其它**：容量与复盘 / 临时笔记 / 收藏链接

侧边栏不再使用「工作台 / 全局 / 工具」这类泛化分组，改为与内容匹配的「规划与推进 / 其它」，分组名允许用户自定义；顶栏不再重复放工具菜单。页面标题做去重：季度页「Q4 季度规划」、周页「第 42 周」、项目页「全局项目」。

所有截止/目标日期字段必须包含 24 小时制 `HH:mm` 时刻；新建表单使用自定义日期时间选择器，提醒弹窗/系统通知按该时刻与提前量精确到分钟。

期间切换器：年份网格 + Q1-Q4 容量卡片 + 指定周跳转；⌘K 可搜索「2026 Q4」「第 42 周」「等保」等并跳转；←/→ 切换期间（功能版）。

### 3.1 核心对象

| 对象 | 关键字段 |
| --- | --- |
| 分类 Category | 名称、颜色、默认提醒、排序、归档；自定义分类可删除，内置分类保留；示例预置应用安全 / 安全运营 / 团队建设 / 其它提醒 |
| 季度任务 Objective | 年、季度、标题、分类、**计划人日 plannedDays**、状态、进度、截止日期 + **24h 时刻 dueTime**、关联项目、提醒规则 |
| 本周安排 WeekTask | ISO 周、标题、分类、截止日期 + **24h 时刻 dueTime**、**预计人日 estimateDays**、状态、关联季度任务、关联项目/里程碑、提醒 |
| 长期项目 Project | 标题、分类、状态、起止日期 + **结束时刻 endTime**、**全局总规划人日 plannedDays**、**工作项 workItems[]**、里程碑列表、关联季度任务；项目为全局维度 |
| 项目工作项 ProjectWorkItem | 标题、**规划人日 plannedDays**、**安排周 weekKey**、状态；按安排周自动进入对应本周安排，并计入当前季度排期 |
| 里程碑 Milestone | 标题、目标日期 + **24h 时刻 targetTime**、权重、状态、提醒 |

| 笔记 / 链接 / AI 会话 / 设置 | 本地存储 |

> 所有日期字段统一带 `HH:mm` 24 小时制时刻；提醒弹窗与 macOS 系统通知按截止时刻 + 提前量精确到分钟计算，不允许只存日期。

### 3.2 页面

- **季度规划**：本季度容量卡（可用人日/已占用/剩余/完成度 + 分类堆叠条）、季度任务列表、季度日历、分类分配环图、年度总览、统计入口；
- **本周安排**：上一周 / 下一周 / 回到本周、7 天日期条、周容量、**项目自动排期**、本周事项、逾期移入、关联季度任务/项目；
- **全局项目**：项目概览行（全局规划 / 本季排期 / 已拆解 / 里程碑 / 风险 / 进度）→ 点击进入项目工作规划详情（全局总规划 / 工作项 / 安排周 / 本季度排期 / 全局里程碑）；
- **容量与复盘（工具）**：年/季/月/周工作日与人日、工作日历热力图、分类人日、季度拆分表；
- **临时笔记 / 收藏链接（工具）**：Markdown 编辑预览；链接以集合 + 列表管理，支持添加/编辑/删除、自定义集合标签、搜索和系统浏览器打开；
- **AI 抽屉**：对话、上下文范围、提案卡、确认写入；
- **设置**：皮肤、启动、人日/日历、**分类管理（可新增/删除自定义分类）**、**侧边栏分组命名**、提醒、AI、数据。

## 4. 关键规则

### 4.1 中国日历与容量

- 数据源：内置官方节假日数据（2024–2026），设置里可检查更新 / 手动编辑 / 导入 JSON；
- 判定：调休上班日 → 工作日；法定假日 → 休息；其余周一至周五 → 工作日；周末 → 休息；
- 容量 = 期间工作日 − 请假/占用天数（单位：人日）；
- **2027 官方安排未发布时**：明确提示“按周末规则估算，可手动补充”，绝不让 AI 编造节假日；
- 日期存 `YYYY-MM-DD`，时间存带时区 ISO，避免跨时区错误。

2026 Q4 示例：62 个工作日 − 2 天年假 = **60 人日可用**；本季度任务 48 人日 + 项目本季排期 10.5 人日 = 已占用 58.5 人日（98%），完成度 32%。2026 全年 248 个工作日 / 246 人日可用（扣请假后）。

### 4.2 周与季度边界

- 周用 ISO 8601，周一为起点；跨季度周显示拆分，例如“Q1 3 天 + Q2 2 天”；
- 周页面按 dueDate 归属周；逾期项可“移入本周”；
- 季度任务可跨季度（通过关联项目），统计按截止日期归属；
- 项目工作项按 `weekKey` 自动聚合到对应周，不复制事项；修改安排周即移动，勾选完成同步回项目；原型已支持 2026 Q4 → 2027 Q1 的周次（如 2027-W01 ~ W03）。

### 4.2.1 项目工作规划与自动排期

- 项目有独立的 **全局总规划人日**，可随时调整；
- 项目可拆成多个 **工作项**，每个工作项有规划人日和安排周；
- 安排周落到某周后，该工作项自动出现在本周安排的「项目自动排期」，并计入该周已排人日；
- 周页勾选完成 → 项目工作项状态同步；项目进度仍按全局里程碑等权计算；
- 超载不阻塞保存，但周容量显示红色负剩余和“超载”提示，提醒用户挪出人日。

### 4.2.2 本季度 vs 全局项目

- 项目是 **全局维度**：总规划、工作项、里程碑可跨季度；
- 本季度只统计安排周落在当前季度的工作项人日（`本季度排期`）；
- 季度规划的本季度容量 = 季度任务人日 + 项目本季排期人日；跨季度部分不计入当季，避免把未来季度的时间压到本季度；
- 剩余人日 = 可用人日 − 已占用，允许为负；负值即超载；
- 项目结束日期晚于当前季度末，或项目状态为 risk，则标 **有风险**；跨季度项目额外标 **跨季度**；
- 项目详情同时展示 `全局总规划`、`全局已拆解`、`本季度排期`、`全局工作项完成`，明确区分两个 scope。

> 当前原型的“季度任务人日”与“项目本季排期人日”相加作为已占用；若实际工作中项目工作项只是季度任务的执行拆解、不应重复计入，下一版可改为只计一次。

### 4.3 提醒

- 规则继承：全局默认 → 分类默认（可选）→ 单事项覆盖；
- 预设提前 5 天 / 2 天 / 1 天 / 12h / 6h / 3h / 1h / 30 分钟 / 自定义；
- 只有日期的事项默认当天 09:30；
- **应用内顶部弹窗**（不抢焦点，完成/稍后/打开，20 秒自动消失）+ 可选 macOS 系统通知；
- 启动 / 唤醒补发错过的提醒，聚合成一条；勿扰时段可配置；菜单栏红点。

## 5. 技术方案

### 5.1 选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 壳 | Electron 44 | 刘海窗口 / 菜单栏 / 通知 / 自启最成熟 |
| 渲染 | React 19 + TypeScript + electron-vite | 复杂规划 UI 组件化；复杂状态可维护 |
| 状态 | Zustand + IPC 快照 | 单窗口、数据量小 |
| 校验 | Zod | IPC / AI 工具参数 / 导入数据统一校验 |
| 日期 | date-fns | ISO 周、期间计算 |
| UI | 自建 CSS tokens + Phosphor 图标 | 四套皮肤精确控制，不引重 UI 库 |
| 存储 | JSON 文件 + 原子写 + 每日备份 | 无原生依赖、可读可迁移 |
| 打包 | electron-builder（arm64 DMG，ad-hoc） | 与原版一致；可升级公证 |

不复用原版 1.4 万行业务代码；保留交互范式、设计语言与刘海窗口经验，代码重写。

### 5.2 架构

```
Electron Main（唯一数据权威）
├─ window/panel.ts        刘海折叠/展开/多屏/固定/失焦收起
├─ window/reminder.ts     顶部提醒弹窗（不抢焦点）
├─ services/store.ts      JSON 原子写、备份、schema 迁移、导入导出
├─ services/calendar.ts   节假日数据 + 工作日/容量计算
├─ services/reminders.ts  调度、补发、稍后、勿扰
├─ services/ai.ts         OpenAI 兼容 + SSE + 工具执行 + 确认状态机
├─ services/metadata.ts   链接标题/favicon + SSRF 防护
└─ ipc.ts                 Zod 校验
        ↕ contextBridge（sandbox: true，无 Node）
Renderer（React 19）
├─ 3 个主页面 + 3 个工具页 + AI 抽屉 + ⌘K
├─ 组件 PeriodSwitcher / CapacityBar / ObjectiveRow / TaskRow / AutoWorkRow /
│       ProjectPlanner / WeekSwitch / MilestoneBar / ReminderChip / ProposalCard / Heatmap
└─ themes: noir / ops
```

### 5.3 存储

工作区目录（默认 `~/Library/Application Support/Q-Panel/workspace`，可迁移）：

```text
workspace.json      # 设置/分类/季度任务(plannedDays)/周任务(estimateDays)/项目/工作项/里程碑/人日调整
notes.json          # 笔记正文
links.json          # 链接
ai-history.json     # AI 会话
reminder-state.json # 已触发/稍后/勿扰
backups/            # 保留最近 14 天
```

写入 `.tmp` → rename 原子替换；`schemaVersion` + 迁移；导入前校验且不覆盖；单实例锁；崩溃从备份恢复。

### 5.4 AI

- 主进程直接请求 `${baseUrl}/chat/completions`，SSE 流式转给渲染层；Key 只在主进程，`safeStorage` 加密；
- 工具：`get_period_summary`、`search_items`、`create_objective`、`update_objective`、`create_week_tasks`、`update_week_task`、`create_project`、`add_milestone`、`complete_milestone`、`set_reminder`、`get_capacity`；
- 流程：tool_calls → Zod 校验 → 提案卡 → 用户确认 → 事务写入 → 结果回传模型；
- 不支持工具调用的模型回退 JSON 块解析 + 校验 + 重试一次；
- 上下文范围可设：最小 / 摘要（默认）/ 全部；笔记和链接默认不发送；AI 不能删除事项。

### 5.5 安全

- `contextIsolation`、`sandbox`、`nodeIntegration: false`；preload 白名单；
- 严格 CSP；`will-navigate` / `window.open` 拦截；IPC Zod 校验；
- 链接抓取：仅 http(s)、禁内网/回环/非法重定向、6s 超时、2MB 上限；
- 零遥测；除配置的 AI、手动检查节假日、链接元数据外不发起请求；
- 外部链接仅 `shell.openExternal` 打开 http/https。

### 5.6 测试与验收

- 单测：日历/容量、季度/周边界、提醒偏移与补发、里程碑加权、存储迁移、AI 工具校验；
- 集成：mock OpenAI 服务跑“一句话建 3 条周任务 → 确认 → 落库”；
- E2E：Playwright 启动 Electron，展开面板、建季度任务、建项目工作项并验证本周安排自动排期、新增分类、截图四套皮肤、重启验证持久化；
- 手动验收清单每阶段给用户实际使用。
